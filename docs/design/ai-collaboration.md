# AI 分工、第一里程碑與擴充交接

2026-10-20。使用者計畫：先由本 chat 的 AI 製作第一里程碑，再由其他 AI 擴充角色、造型、地圖、敵人、劇情。以下責任配置與新增驗收為建議，尚未開始實作；六名少女／一個星域、資料化及基本編輯能力沿用既有需求。

## 1. 持續保留整合責任

使用者負責方向、優先順序、重要玩法與品質樣本的接受；整合 AI 負責讓每批產物能一起運作。初期可由第一里程碑作者繼續整合，之後可依文件交接給另一 AI。不同角色不一定需要不同模型，也不需要同時啟動所有 AI；建議先以整合、內容、素材三路工作，驗收由另一輪獨立檢查執行。

| 角色 | 可負責的產物 | 邊界 |
| --- | --- | --- |
| 核心／整合 AI | 模擬、平台、載入、共用 schema、技能原語、存檔遷移、編輯器基礎、建置與整合 | 統一維護共用契約，審查與合併各包；不要成為每份資料的手動編寫者 |
| 角色／戰鬥內容 AI | 角色、成長表、既有技能組合、敵人、掉落與取得來源 | 使用已支援能力；新機制提交需求，不自行改核心或傷害公式 |
| 世界／關卡 AI | 星域、星球、據點、敵群、遭遇、Boss 階段配置、解鎖與獎勵 | 遵守共用難度／經濟基準；新 AI 行為先經核心擴充 |
| 美術／造型 AI | 立繪、頭像、SD、造型、背景、VFX 與素材 manifest | 依核定樣本和素材契約；造型與角色身分分離，不順手改戰力 |
| 劇情 AI | 故事節點、對白、任務文字、角色語氣、在地化 | 共用世界觀／時間線／詞彙表；觸發及獎勵使用既有條件與交易 |
| 音效 AI | 共用音色方向、技能／命中／介面音效、cue 對照 | 遵守音量、尾音與混音契約；不以音檔時長決定傷害時間 |
| 驗收／平衡 AI | 指定版本的引用、可達性、存檔、戰鬥、效能、視覺與平衡報告 | 報告要可重現；平衡修改另給明確資料範圍，不自行全面重設 |

同一角色與其造型可分派不同工作，但要約定依賴版本；地圖與故事也應透過事件 ID／旗標契約銜接。避免多人同時修改一個共用大檔。

## 2. 第一里程碑的建議交付

第一里程碑建議包含以下六項；不是只交可操作的展示。這是對既有製作計畫的交付建議，具體系統及角色名單仍依主規格的確認狀態安排。

1. **完整品質切片**：六名少女、一個星域，探索、戰鬥、經營、收集與成長形成循環；桌機／手機各自可用，存檔與匯出入可驗證。
2. **可擴充核心**：版本化資料契約、技能／條件／事件原語、內容載入與依賴校驗、資產 registry；沒有角色 ID 特例。只實作切片需要且可重用的能力，不預造所有想像中的系統。
3. **基本編輯器 E1／E2**：看得到各類內容，能改數值、換素材／已支援技能、星級與取得方式；存草稿、隔離試玩、匯出再匯入。進階地圖／技能視覺編排可後續追加。
4. **一致性基準包**：核定的代表角色立繪／頭像／SD、桌機手機畫面、技能演出、音效樣本，以及風格、尺寸、命名、色彩、語氣、單位與平衡基準。尚未核定的樣本不能當作已接受。
5. **接力工具與文件**：新增角色／造型／敵人／星球／劇情範例、資料包範本、實際可用的校驗與預覽命令、能力支援清單、遷移與停用說明。具體程式目錄及命令在實作時落地，本文件不宣稱目前已存在。
6. **獨立擴充演練**：交接者依文件新增測試角色、敵人與星球／事件，僅沿用既有能力；自動出現在圖鑑、能編輯並在測試遊戲出現。另驗證換造型、匯出入，以及持有角色／身處區域所屬包停用時的備份、提示與遷移。測試包不擴大正式六名／一星域的數量承諾。

演練通過代表既有能力可由資料擴充；不能保證任意新玩法皆不需程式。若演練必須補核心或靠口頭解釋才能成功，應修正契約／工具／文件後再交付。

## 3. 固定契約，讓內容包各自成長

- 分開記錄引擎能力版本、資料 schema 版本、內容包版本與存檔版本；使用相容範圍與明確遷移，不用單一版號假設全部相容。依賴缺失、循環、重複 ID 與不支援能力在載入前給出診斷。
- 使用穩定命名空間 ID，先分配每個包的命名空間；檔名／中文顯示名／陣列位置不能作身分。造型引用角色，不複製一套角色與技能。
- 各 AI 修改自己的包與局部 manifest。建置器按明確清單產生總索引／圖鑑資料；全域載入順序與覆寫政策由整合者維護，不靠目錄掃描順序決定勝負。新增正式包仍需明確納入發布。
- 核心、遊戲 UI、編輯器共用 schema、計算與校驗。內容新增後應自動可查；新能力須同時處理遊戲支援、編輯欄位／診斷及相容性。
- 內容修改不直接修改玩家存檔。刪除用 active／retired／removed 與遷移處理；確認引用、持有角色、進行中任務及所在地影響，禁止默默丟失進度。
- 平衡共用等級、稀有度、資源費用、傷害／時間單位與代表戰鬥情境；角色或關卡 AI 以基準比較，不各自發明星級倍率。原作值、推論、新設計各有來源標記，研究封存資料維持唯讀。

## 4. 每批工作的實際流程

1. 整合者從已整合 main 建立任務：固定起點 commit、契約／風格／世界觀版本、包命名空間、可改路徑、依賴、目標與驗收。各 AI 使用獨立 branch／worktree；不同 chat／平台也使用同一 repo 與交接檔。
2. 接手 AI 先讀 AGENTS、記憶索引、任務交接及相關契約，再查局部資料。要看核定圖片／影片／音效實物，不能只讀「現代二次元風格」幾個字。
3. 先交一個代表項：角色草圖＋頭像／SD試套、或一個遭遇／故事節點。檢查辨識度、比例、遊戲內呈現與難度，再批量擴充。
4. 若缺能力，提交「想達成的玩法、最小資料例、預期結果、相容／存檔影響」。整合者加入通用能力及必要 schema／編輯支援／測試，再讓內容作者沿用。不得私加 eval、自訂執行腳本或固定角色分支繞過契約。
5. 作者提交小批次 commit／PR、校驗結果、桌機／手機必要預覽、資料來源、已知缺口與交接。美術交付記錄模型／版本／提示與修整來源，最終品質依遊戲內結果驗收，不能只以提示詞相同視為一致。
6. 整合者逐批合併，處理共用檔衝突與版本；以合併後版本驗必要引用、可達性、受影響循環及存檔相容。獨立驗收記錄實際 build、內容版本、裝置／seed／步驟；未實測項明列。
7. 先在作者隔離測試遊戲套用，通過後依內容包與既有 repo 發布流程導入正式版；保留前一版本與可回復存檔。編輯器按儲存不等於正式發布。

整合 AI 可更換，但每次只有一位承擔當批整合責任。避免讓多位 AI 同時直接在 main 重構共用模組。

## 5. 給下一個 AI 的任務範本

下列是待填的任務文字範本，不是現在已分派的工作；實際路徑以 M1 落地結果填入。

```text
任務：擴充［內容包／角色／區域］
起點：main 的［commit］；依賴［包及版本］
先讀：AGENTS.md、docs/memory/index.md、［任務交接］、
      docs/design/content-contract.md 及［相關玩法／美術／世界觀契約］
目標與數量：［具體交付］
命名空間：［已分配 ID prefix］
可修改：［此包路徑、素材路徑、局部 manifest、任務交接］
共用契約由整合者維護；新機制先提最小例與影響，不自行改核心。
一致性依據：［核定樣本與版本］；平衡基準［情境／單位／對照角色］
驗收：［實際校驗命令、試玩步驟、素材規格、裝置及截圖／錄影狀態］
交付：commit／PR、資料來源與新設計差異、驗證結果、已知缺口、下一步。
```

發派「擴充角色」前應列出可用技能能力、預算與取得位置；發派「寫劇情」前列旗標、獎勵與事件介面；發派「畫造型」前附角色基準圖及立繪／SD／頭像關係。缺少這些資料，先完成任務定義。
