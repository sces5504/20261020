# 內容圖鑑與網頁編輯器

> 目前生效：Galaxy Angel 0.3，先讀 [0.3契約](galaxy-angel-v3.md)、[0.2探索](exploration-v2.md)及[最新交接](../handoffs/galaxy-angel-v3-20261021.md)。本文件較早的防衛／訓練／舊分支／未有Q圖等敘述為歷史狀態，以新版明確契約與實際程式為準。


版本：0.6 新增需求草案｜2026-10-20。使用者已要求額外網頁，查看角色、敵人、Boss、星球等並調數值、外觀、技能、星級與取得方式；已選先個人測試、匯出內容包後正式發布。實作分期尚待確認，不是已製作的編輯器。

## 1. 產品目標與入口

遊戲與編輯器共用內容schema、效果registry、資產manifest、校驗器與預覽計算，避免做出一個表面可修改、實際遊戲卻不讀的管理頁。

路由提案：遊戲 `/#/play`、內容工具 `/#/studio`，均相對專案部署base path，也可各自建置為同repo不同入口。這是獨立工作介面，不塞進一般遊戲流程。桌機優先編輯，手機可瀏覽與基本修改；複雜波次／技能編排的手機體驗另行驗證。

兩個工作模式：內容圖鑑可讀取目前內容快照；作者模式在草稿上修改並預覽。一般玩家存檔和編輯專案分開，不讓改一張卡的基礎數值等同直接修改玩家倉庫。

## 2. 圖鑑與狀態

| 分類 | 列表與篩選 | 詳情與關聯 |
| --- | --- | --- |
| 少女 | 頭像、名稱、星級、分類、標籤、取得來源 | 基礎／指定等級能力、成長、技能、素材、配方／掉落／任務引用 |
| 敵人 | 外觀、類型、能力、行為、出現區域 | AI、武器、技能、掉落、使用它的波次 |
| Boss | 外觀、階段、關聯遭遇、可實作狀態 | 階段條件、技能／彈幕、預警、獎勵 |
| 星球 | 所屬星域、資源、啟動費用、面積／電力 | 建築、人力、防衛、事件與解鎖 |
| 技能／建築／配方／道具 | 依schema產生對應摘要與條件 | 參數、效果／成本、素材、來源與反向引用 |

列表從registry／內容索引生成，不硬寫六名少女或單一星域。Boss以內容定義的類型／標籤識別，不靠五星或名稱猜測。

狀態必須可辨：研究來源、已匯入草稿、已配置、行為未支援、素材缺失、可試玩、已發布、已退休。研究CID342列不是342名已做好的少女；發布清單不得混入未實作來源後顯示成「遊戲已有」。可在來源檢視查表與證據，但不能把猜測當已實現的功能。

## 3. 可編輯內容

| 功能 | 編輯範圍 | 必要回饋 |
| --- | --- | --- |
| 基本資訊 | 名稱、描述、標籤、分類、基礎星級 | 顯示變更與被引用位置；星級不等同等級／突破tier |
| 數值 | 生命、攻擊、防禦、速度、射程、技能間隔等已命名欄位 | 單位、上下限、原值／新值、指定等級的有效值預覽 |
| 成長 | 曲線引用、級別上限、已支援成長參數 | 預覽數個等級，區分來源與新平衡 |
| 外觀 | 立繪、頭像、SD、敵人／Boss／星球圖、VFX、音效 | 上傳／選庫、裁切、pivot、安全區、動畫與音訊預覽 |
| 技能 | 替換已註冊技能、技能等級／允許參數、目標與效果組合 | 使用實際技能schema驗證、描述同步、試放與未支援提示 |
| 取得方式 | 召喚候選／配方、掉落、任務、解鎖、商店等已支援途徑 | 顯示實際引用與生效模式，校驗空池／失效條件 |
| 世界／遭遇 | 星球條件、據點、波次、Boss／敵人引用、獎勵 | 前置／可達性／生成與時限預覽；複雜視覺編排可後續加入 |
| 生命周期 | 複製、新增、停用、退休、刪除 | 引用影響、舊檔處置與遷移預覽 |

數值表單編輯的是定義／曲線，不是暫時buff後的最終數字。換星級不自動把生命／傷害等全部乘倍率，除非規則明定；UI列出它會影響的候選、取得條件與顯示。

取得方式是可有多個來源的關聯，不是一個無法連動遊戲的文字欄。新增掉落需指定對象、數量／權重與條件；更換稀有度或移出召喚池後重新驗證原生距離／分支規則，不能默默使角色不可取得。

## 4. 技能的能力邊界

第一步可選用已實作技能與調參；第二步以已註冊原語組合新技能，如傷害、護盾、治療、增益、彈幕、砲台。不同type的表單與校驗由registry提供。

全新行為仍需程式擴充，例如新的時間機制、全新碰撞或無支援的目標選擇器。完成後註冊schema與預覽，才成為編輯器可選項。不以執行任意JS、按名字猜效果或no-op假裝全技能可編輯。

原作未賦義fNN保留在唯讀來源檢視，不把未知欄位包裝成可調的「傷害倍率」。原始研究檔不被編輯器覆寫；作者修改產生override／新定義並留來源關係。

## 5. 外觀與音效替換

選檔後先檢測格式、尺寸、透明度、動畫／atlas依賴、可解碼性與預算，再建立AssetDef。圖片替換可保留原assetId並新增版本，或建立新ID後變更角色引用；不依檔名猜角色，也不覆蓋其他共用素材。

草稿媒體以IndexedDB的blob與manifest保存，object URL只作當次預覽，不寫進可發布資料。匯出內容專案包包含媒體實檔及相對引用；不能只有JSON指向作者電腦路徑。

不同用途分別交付立繪、頭像、SD與動畫；換立繪不自動宣稱已重做戰鬥動作。聲音可選庫／替換、試聽與調音量／播放策略，BGM、SFX、語音類別分開。更換外觀或音檔不改碰撞、射程或傷害時點。

AI產生素材先作製作資產再導入，不要求玩家遊玩時即時生成。編輯器內建AI生成按鈕不是這次已要求的必要功能，供應商／API／費用要另立需求；不把金鑰放進公開網頁。

## 6. 草稿、預覽與發布

```mermaid
flowchart LR
  A[已發布內容版本] --> B[複製為作者草稿]
  B --> C[表單編輯／替換素材]
  C --> D[校驗與影響報告]
  D --> E[隔離試玩／技能預覽]
  E --> C
  D --> F[匯出可發布內容包]
  F --> G[建置與發布新版本]
```

| 操作 | 意義 |
| --- | --- |
| 儲存草稿 | 僅保存作者工作，不修改正式遊戲或玩家存檔 |
| 預覽／試玩 | 載入草稿快照與獨立測試存檔，可重設，不消耗正式進度 |
| 匯出專案 | 備份／跨裝置轉移草稿與媒體，可含未完成項目但標草稿 |
| 匯出發布包 | 通過必要校驗、含版本／hash／完整依賴與媒體 |
| 正式發布 | 明確選擇的新版本部署，不等同按下儲存 |

使用者已選「先在自己的測試遊戲生效，匯出內容包後再發布正式版」。不做網頁直接寫GitHub或立即更新所有玩家；第一階段不需要作者登入、發布後端或雲端草稿服務。

GitHub Pages載入編輯器、保存本機草稿與執行預覽；正式發布由匯出包進入既有GitHub／CI流程，驗證後產生新版本。未來若改成網頁直接發布再另設授權服務，不將該服務當目前必要依賴。

### 已選模式的操作流程

編輯表單／換素材 → 自動保存草稿 → 校驗 → 按「套用至測試遊戲」→ 新的測試快照與隔離存檔 → 回編輯器繼續調整 → 匯出專案或發布包。遊戲畫面明示測試模式與版本，可重設／退出；不把測試角色／掉落寫進正式進度。

匯出格式提案為標準ZIP：manifest／版本與base鎖、definitions或overrides、locales、assets媒體與必要遷移描述。專案備份另外含作者歷史與未完成狀態；可發布包只含通過驗證的runtime內容。匯出前列變更、引用與存檔影響，不要求使用者手改JSON。

本機草稿可同瀏覽器重開，換裝置以匯出／匯入專案轉移；尚無自動同步。匯出發布包本身不觸發上線，之後由作者／AI依repo建置流程導入、審閱、提交及部署，沿用版本與回復紀錄。

## 7. 共用核心與資料邊界

- `ContentSchema/Registry`：遊戲與編輯器同源，表單、選項、單位、條件與校驗不手抄兩套。
- `PublishedContent`：不可變的已發布版本；`EditorProject`：含base版本、revision、patch、新定義、素材與操作歷史；`PlayerSave`：玩家進度。三者不互相當成同一JSON。
- 編輯歷史具undo／redo、自動草稿保存、重載恢復與差異比較。無效草稿仍可備份；阻止的是帶必要錯誤的試玩／發布，不是讓作者失去編輯成果。
- 改動在安全點生成新ContentSnapshot。正在戰鬥不因另一頁修改技能而突然換規則；試玩重開該遭遇或明示重新載入。
- 來源表、配方與原生證據保持不可變；內容override與來源引用並存，標註「原作／調整／新設計」。

## 8. 校驗、引用、存檔與回復

保存草稿可有錯誤，報告具體檔案／欄位與修復方向。試玩／發布校驗至少包括數值範圍、ID／引用、必要素材、效果支援、空配方池、前置循環與主線可達。

刪除前展示反向引用：編隊、召喚、掉落、任務、波次、研究與素材共用。可停用／退休或選替代項；真正移除還需處理舊存檔角色、位置與工作。不能點刪除後才讓遊戲crash。

新發布內容對既有玩家的影響要有預覽：星級／曲線變更、生命上限、角色退休、任務與取得來源。具體遷移策略另依既有存檔契約，不默默移除已取得角色。回退內容版本不等於任意回退玩家資源或套用舊schema。

匯入另一份專案或碰到base版本更新時，提示衝突與差異，不用最後寫入直接覆蓋。初期單作者，不預設即時多人協作。

## 9. 分期提案

| 階段 | 交付 |
| --- | --- |
| E0 資料基礎 | 共用schema、registry、素材manifest、版本與反向引用索引，從遊戲架構開始準備 |
| E1 內容圖鑑 | 各類目前內容、搜尋／篩選、詳情與狀態；可區分研究來源與實際可玩 |
| E2 基礎編輯 | 數值／星級／技能替換／取得來源／素材、草稿、undo、預覽、匯出與校驗 |
| E3 進階工具 | 技能原語組合、波次／地圖視覺編排、批次平衡分析；直接發布不是已選需求 |

使用者要求的是具備編輯能力的額外網頁，E1不能取代E2作為全部交付。建議E0隨核心先做，E1／E2在擴充大量內容前完成；具體是否與第一切片一起交付仍屬分期提案，不擅自擴大第一切片工期。
