## 2. 第一可玩切片（數量皆為提案）

- 一個小星域，三顆可互動星球、數個據點與一名多階段首領；用資料解鎖與連線。
- 六名可用少女，涵蓋遠程、近戰、範圍傷害與支援行為；每名有立繪、頭像、SD 與技能呈現。
- 完整航行、目標、普通攻擊、技能、閃躲、勝敗與整補。
- 配方召喚、資源收入／消耗、星球啟動、建造、派駐、生產、一條研究鏈。
- 一條短故事任務與一次避彈訓練，能完成「探索—收益—發展—再挑戰」。
- 存檔、自動保存、匯出／匯入、離線結算及一個舊內容遷移樣本。
- 桌機寬螢幕、手機直式兩套布局；觸控、音訊、低特效與更新流程。

切片不是最終內容規模；全角色與全區域數需 P1 盤點才能定義。不以「商業品質」等同立即承諾完成百名角色，也不以少量內容縮減使用者的原作保留要求。

## 4. APK／既有逆向資料的調查順序

目前無需 APK 才能完成 0.1 規格；若要精準內容、數值與技能，建議接著提供。優先順序：

1. package、versionName／versionCode、地區／語言、檔案 hash、是否另有資源包，先確立版本。
2. 已讀出的角色、技能、敵人、成長、召喚、建築、研究與關卡表；CSV／JSON／文字說明比單純大型反編譯目錄更容易對照。
3. 傷害、目標、移動／編隊、召喚選池、時間與星球失守相關函式；記錄來源類別／欄位／方法，不只貼最終解讀。
4. 資產索引與預覽：立繪、頭像、SD、動畫、UI、字體、特效、音樂與聲音；標尺寸、格式、依賴與使用狀態。
5. 用可重複情境交叉核對公式；伺服器缺失部分列出替代規則與設計理由。

靜態分析先行，不預設執行 APK、使用帳號或連舊伺服器；不把憑證、個人資料或整包原作素材推到公開 repo。素材使用方式仍由使用者後續決定。若提供的是已有逆向報告，報告文字同樣只是待核對材料。

## 6. 測試層級與證據

核心單元測試用於傷害順序、條件、交易與資格等真正有風險的邏輯；內容校驗檢查整批資料引用；遷移測試以固定舊檔驗證無遺失與可重跑；整合測試涵蓋交易到存檔、離線到工作；E2E 涵蓋第一循環、跨裝置輸入與載入／存檔。

桌機先測 Chromium；手機至少實測 Android Chrome 與 iOS Safari。桌機 WebKit 模擬不能代替 iPhone 的安全區、觸控、記憶體與音訊驗證。其他桌機 Firefox／Safari 依正式支援矩陣執行；版本與機型在發布時明列，不用「所有瀏覽器」泛稱。

效能報告記錄機型、OS、瀏覽器、viewport、DPR、build、內容版本、seed、數量與量測方法；平均 FPS 之外看 p95 畫格、長任務、記憶體與輸入回饋。沒有真機就記未驗證。

## 7. 品質閘門與範圍界線

發布前必須：核心循環可玩；無進度遺失／重複交易；必要素材、聲音與介面完整；真機觸控通過；效能基線通過；子路徑與版本更新通過；完整內容清單標出仍缺部分。不以功能數量掩蓋品質問題。

本階段不要求：完整伺服器、即時多人、付費金流、玩家帳號、反作弊、公開模組商城、可視化全功能編輯器。原作相關系統仍盤點，是否保留／轉換另列決策，不將它們默認刪出最終目標。

風險與處理：版本混用→差異表；原作公式缺失→APK／實測；全量美術龐大→先切片定品質再分批；手機彈幕成本→早測固定樣本；資料包刪改→遷移；靜態網站無雲存→先匯出／匯入；經濟簡化破壞配方→整體模擬與試玩。
